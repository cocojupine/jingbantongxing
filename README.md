# 鲸伴同行 · 静态 Demo

面向孤独症人士及伴游人员的海洋公园游园演示项目。本仓库统一管理现有页面、静态资源和 UI 稿件，后续代码与界面迭代均在此目录进行。

## 目录

```text
鲸伴同行-demo-发布包/
  index.html       # App 入口
  mockup.html      # 手机样机展示
  assets/          # 已构建的 JavaScript、CSS 和图片
鲸伴同行-UI稿件/
  样机版/
  透明背景版/
```

## 本地运行

安装 Python 3 后，在仓库根目录运行：

```powershell
python -m http.server 5173 --bind 127.0.0.1 --directory "鲸伴同行-demo-发布包"
```

- App：http://127.0.0.1:5173/
- 游园首页：http://127.0.0.1:5173/#/main
- 手机样机：http://127.0.0.1:5173/mockup.html

请通过 HTTP 服务预览。直接双击 HTML 文件可能无法加载 JavaScript 模块。用 `Ctrl+C` 停止服务。

## 当前基线

- 已包含身份选择、登录注册、个人档案、小白助手、语音交互演示、感官友好书包预约、社交故事和场馆信息页面。
- 本期交付范围为静态页面及演示交互。账号、档案、绑定和预约使用浏览器本地存储；助手回复来自内置知识库。
- 伴游人员可协助填写心青年档案；伴游身份分为「志愿者」「场馆工作人员」。伴游人员关联心青年时固定显示「心青年（陪伴对象）」，心青年关联伴游人员时选择对应人员类型。
- 园区地图仍为占位入口。已包含行前五感问卷、行后反馈问卷、五维感官画像雷达图和伴游关注要点。
- 语音功能依赖浏览器支持，部分情况使用模拟内容；字体引用 Google Fonts。
- 初始提交仅有构建产物和 UI 图片，没有原始 React/TypeScript 工程，也没有 `package.json`。发布包中的源码路径标注不代表源码文件已包含，因此不能直接运行 `npm run dev`。

## 登录后的资料填写指引

- 登录或注册成功后，首页提醒位先显示精简的「完成游园准备」卡片，提供「完善心青年档案」和「完成感官测评」两项行动。
- 两项准备完成前不展示白鲸演出等常规提醒；两项都完成后，填写卡片自动替换为原有提醒内容。
- 点击档案入口进入「我的」并打开现有编辑弹窗；测评入口进入现有 17 题行前感官问卷。建档状态、档案完善度及问卷进度均读取当前账号的真实本地记录，仅点击入口不会标记完成。
- 伴游人员先关联心青年，再查看陪伴对象的测评结果；问卷由心青年使用本人账号填写，避免保存到伴游账号。填写入口仅保留在首页提醒位，不在「我的」页面重复展示。
- 可维护模块为 `鲸伴同行-demo-发布包/assets/login-guide.mjs`、`login-guide.css` 与 `guide-goldfish.svg`。发布包仅对现有登录成功跳转做定点修改，将 `setup=1` 改为 `guide=1`；手动预览首页填写卡片可访问 `/#/main?guide=1`。
- 本次仅做静态语法与代码审阅，未运行测试、构建或浏览器交互检查。

## 行前问卷预览

- 问卷页面地址为 `/questionnaire/`，可从心青年端「我的」页面进入。
- 心青年端完成问卷后，「我的」页面会展示五维感官画像雷达图和「编辑问卷」入口；未完成时展示「填写问卷」入口。关联服务对象后，伴游人员端也会展示该对象的雷达图及静态陪伴关注要点。
- 题目和选项逐字采用 `file/questionnaire.js` 的五感 17 题。本版供内容与交互评审，问卷版本尚待最终确认。
- 行前与行后问卷首页使用同一套淡蓝背景、线性图标、居中标题与开始按钮样式，保留题量和简短说明；答题页采用紧凑布局。
- 首页题量信息只显示一次：未填写时显示「共 N 题」，已有填写记录时显示「已填写 X / N 题」。两份问卷均移除右上角「我的」，使用左侧返回；所有交互均属于静态前端演示，没有接入后台。
- 支持逐题选择、返回修改、未完成校验、完成页及当前浏览器暂存。最后一题点击「完成」直接保存并进入完成页，不经过答案检查页。完成后可从「我的」页面选择「编辑问卷」查看或修改原答案。
- 答案按当前演示账号分开保存，不向服务器发送；没有接入第三方表单或生成 AI 报告。
- 可维护页面位于 `鲸伴同行-demo-发布包/questionnaire/`。运行 `node scripts/sync-questionnaire.mjs` 可同步题库并安装入口；原发布包只插入一个 React 链接和独立样式引用。
- 检查命令：`node --test scripts/questionnaire.test.mjs`。
- 本次通过内容一致性、存储边界、角色入口及 DOM 填写流程检查。浏览器连接不可用，尚未完成实际浏览器截图与布局验收。

## 行后反馈问卷

- 「我的」页面在「我的书包预约」与「社交故事」之间增加「反馈问卷」入口，沿用现有列表和线性图标样式。
- 页面地址为 `/feedback/`，复用行前问卷的极简白色页面样式。
- 原稿为 `file/行后问卷.docx`，来自 GitHub 提交 `f8d9a99`，包含 14 题、44 个文字选项及末题的五星评分。
- 运行 `python scripts/sync-feedback-source.py` 可从 Word 的文字和星形对象重新生成 `feedback/source.mjs`，保留原始题目、选项及文件校验值。
- 填写逻辑支持单选、多选、五星评分、逐题导航、直接完成与本地暂存；答案按账号和角色隔离，独立于行前问卷。检查命令为 `node --test scripts/feedback.test.mjs`。
- 已按用户确认保留全部 14 题及伴游人员相关选项。「不适的感官」和「不适的场馆」支持多选，其余选择题单选，末题为五星评分。
- 感官选择「无」时与其他感官互斥，并跳过不适场馆题；重新选择某项不适后恢复场馆题。最后一题点击「完成」直接保存，不经过答案检查页。
- 小白满意度的五星评分下提供「想补充的话」选填意见框，留空不影响完成；文字随答案暂存，重新查看和修改时保留。
- 两份问卷 URL 加 `?intro=1` 可直接查看首页，包括已填写完成的情况，不清除已有答案。
- 本地体验地址为 `http://127.0.0.1:5177/feedback/`，填写完成后可再次查看和修改。该预览只保存在当前设备，没有接入服务器收集反馈。
