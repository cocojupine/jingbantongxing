# 鲸伴同行 UI 设计规范

## 1. 文档说明

本规范依据当前「鲸伴同行」手机样机页及其实际加载的应用样式整理，用于后续地图 Demo 与相关页面的视觉延展。整体沿用产品现有的海洋陪伴主题、移动端信息结构和无障碍交互习惯。

**参考页面**

- 样机容器：`鲸伴同行-demo-发布包/mockup.html`
- 应用入口：`鲸伴同行-demo-发布包/index.html`
- 现有样式：`鲸伴同行-demo-发布包/assets/index-BEaoXQS-.css`
- UI 修复与响应式规则：`鲸伴同行-demo-发布包/assets/ui-repairs.css`
- 视觉细化规则：`鲸伴同行-demo-发布包/assets/style-refine.css`
- 视觉参考稿：`鲸伴同行-UI稿件/样机版/`

本文件记录现有界面的设计基线。表格中的设计令牌以当前发布样式为准；涉及新页面的布局建议均应在地图 Demo 实际内容上验证。

## 2. 设计目标

- **舒缓、友好、易辨识**：以浅色背景、海蓝色强调和留白降低视觉压力，避免大面积高饱和色块。
- **信息清晰、行动明确**：优先展示当前任务、环境提示和下一步操作；按钮文案与操作结果保持一致。
- **结构稳定、可预测**：导航位置、卡片样式、标题层级及返回方式在各页面保持一致。
- **移动端优先、适配无障碍**：支持小屏和内容滚动，保留足够触控面积、安全区留白及键盘焦点状态。
- **装饰服务于内容**：鲸鱼、小白、海洋生物和气泡用于建立陪伴感，不遮挡正文、地图信息或核心操作。

## 3. 手机样机与画布

样机页使用独立的展示画布，画布尺寸和设备外框属于展示效果，不应直接作为应用页面的固定布局。

| 项目 | 现有规格 |
| --- | --- |
| 样机展示画布 | 1080 × 1440px，居中等比缩放，缩放比例不超过窗口适配值 |
| 手机外框 | 419 × 878px，深石墨色机身，62px 外圆角，13px 边框 |
| 手机屏幕 | 393 × 852px，49px 圆角，内容超出屏幕时裁切 |
| 灵动岛 | 118 × 33px，顶部居中，纯装饰且不拦截交互 |
| 应用常规预览基准 | 最大宽度约 375px，最大高度约 812px |
| 小屏全屏模式 | 视口宽度不大于 600px 时应用铺满视口，取消手机外壳圆角和投影 |

手机样机周围使用近白色背景和顶部淡蓝色径向光晕。样机页的品牌角标、英文副标题和设备按键属于展示层，不进入应用页面内容。

### 4.3 使用规则

- 主品牌色用于主要操作、当前导航、焦点和重要图标；浅海蓝用于信息容器与弱强调。
- 页面以白色卡片承载内容，底色保持浅蓝灰；避免在正文后使用高饱和渐变。
- 珊瑚色、黄色和绿色仅用于语义明确的标签或状态，不能代替主品牌色。
- 状态不能只依靠颜色表达；同时提供文字、图标或形状线索。

## 5. 字体与文字层级

### 5.1 字体

- 中文正文优先使用 `PingFang SC`。
- 系统回退顺序：`SF Pro Display`、`-apple-system`、`BlinkMacSystemFont`、`Helvetica Neue`、无衬线字体。
- 页面入口已加载 `Baloo 2` 与 `Fredoka` 字体。仅在现有品牌展示字或数字样式中延续使用，不用于长段正文。

### 5.2 层级

| 文字角色 | 参考字号 | 字重 | 使用场景 |
| --- | ---: | ---: | --- |
| 欢迎语 / 页面主标题 | 19px | 700 | 首页欢迎语、主要身份或页面标题 |
| 卡片标题 / 区块标题 | 15px | 700 | 演出、故事、场馆和卡片标题 |
| 菜单标题 | 15px | 500–600 | 我的页面菜单及主要列表标题 |
| 正文 | 14–16px | 400–500 | 卡片说明、列表内容、问卷题目 |
| 辅助说明 | 12–13px | 400 | 时间、地点、解释文字、次要信息 |
| 小标签 | 11–12px | 500–600 | 状态、类别和辅助徽标 |

正文优先使用 `ink-900` 或 `ink-600`；辅助信息不能低到难以辨认。行高应保证中文阅读舒适，说明文字通常使用 1.5–1.65 倍行高。避免连续使用全大写英文或过长的英文副标题。

## 6. 布局与间距

- 以移动端单列纵向阅读为主，重要内容按「页面标题 → 当前状态 / 任务 → 主内容 → 辅助说明」排序。
- 内容区左右留白通常为 16px；页面主体使用稳定的单列宽度，不在 320px 小屏上产生横向滚动。
- 常用间距以 4px 为步进，优先使用 4、8、12、16、20、24、32px；相邻卡片之间保持明确且统一的间距。
- 首页主体内边距参考 `14px 16px 12px`；可滚动内容需预留底部空间，避免被固定导航或悬浮助手覆盖。
- 分区标题与内容之间保持紧凑关系；分区之间使用更大的留白，不通过额外装饰线制造层级。
- 地图页面优先给地图画布最大可用面积；搜索、筛选和当前位置操作应有稳定位置，图例和说明不应遮挡核心地图区域。
- 长内容由页面主内容区滚动；固定操作区、底部导航与正文内容相互独立。

## 7. 圆角、边框与阴影

### 7.1 圆角

| 令牌 | 数值 | 用途 |
| --- | ---: | --- |
| `r-sm` | 10px | 小标签、输入框、小型控件 |
| `r-md` | 14px | 按钮、常用卡片内部控件 |
| `r-lg` | 20px | 内容卡片、浮层 |
| `r-xl` | 28px | 首页特色卡片或较大的视觉容器 |
| `r-full` | 999px | 胶囊标签、圆形按钮、头像 |

手机样机使用的 62px / 49px 圆角仅适用于设备外壳和屏幕，不作为应用卡片圆角。

### 7.2 边框和阴影

- 卡片优先使用白底与低对比边框 `rgba(18, 60, 110, .065–.08)`。
- 常规卡片采用柔和阴影 `0 2px 8px rgba(14, 75, 133, .06)`；悬浮导航可略加强至 `0 4px 12px rgba(14, 75, 133, .07)`。
- 弹窗、样机或高层级浮层可使用更深的柔和投影；阴影用于区分层级，不作为装饰边框。
- 点击、键盘焦点等状态使用品牌蓝色 2px 外轮廓及清晰的偏移，不单独依赖阴影变化。

## 8. 组件规范

### 卡片

- 内容卡片使用白底、柔和边框和轻阴影，标题、描述、标签和操作顺序保持一致。
- 卡片标题左对齐，文字颜色使用 `ink-900`；说明使用 `ink-600`。
- 卡片内的图标与文字基线对齐；避免插画尺寸挤压标题或可点击区域。

### 按钮

- 每个页面仅设置一个视觉明确的主要操作，使用实心品牌蓝底和白色文字。
- 次要操作使用白底、浅蓝底或文字按钮，避免多个按钮同时呈现为主操作。
- 按钮文案以动作开头且明确结果，例如「查看场馆」「开始填写」「保存修改」。
- 所有核心触控目标最小高度为 44px；相邻操作之间保留可辨识的间隔。

### 导航

- 底部主导航固定在内容之上，使用白色胶囊形容器和轻阴影。
- 当前导航项使用品牌蓝图标和文字；未选中项使用低饱和蓝灰色。
- 固定导航应为内容滚动区域预留底部空间，并适配设备安全区。

### 标签与状态

- 普通状态标签采用浅蓝底与海蓝文字。
- 需要提醒的演出使用浅珊瑚底；平静 / 成功状态使用浅绿色底。
- 标签文字简短，颜色和图标与语义一致；不得仅通过红绿颜色区分状态。

### 图标与插画

- 使用线性图标，默认笔画约 1.8，线端和转角使用圆角处理。
- 同级图标保持统一尺寸、描边粗细和视觉重量。
- 小白、鲸鱼和海洋生物作为陪伴性插画，优先放在卡片外缘或非关键内容区域。
- 地图图标应优先确保定位点、路线和场馆标记在低缩放状态下仍可区分。

## 9. 地图页面延展规则

- 地图是核心内容区域，控件应围绕地图组织，不使用长页面卡片布局覆盖大部分地图。
- 顶部搜索框和筛选入口采用白底圆角容器；搜索结果、筛选面板和场馆详情使用卡片或底部弹层呈现。
- 当前位置使用品牌蓝突出；路线使用明确的主色线条；普通场馆点位使用较浅的海蓝色。
- 不同类型场馆可使用语义图标与文字图例区分；图例颜色需与详情卡和列表标签一致。
- 路线、定位、选中场馆均需提供非颜色状态反馈，例如图标变化、描边、名称或辅助标签。
- 「定位中」「无定位权限」「无路线」「暂无场馆结果」等状态应提供清晰说明和可执行的恢复操作。
- 操作面板应避免遮住用户当前位置和当前选中场馆；展开详情后仍需保留明确的关闭或返回入口。

## 10. 动效与交互反馈

- 动效用于确认操作和维持界面连续性，遵循短促、轻量、不影响内容阅读的原则。
- 样机 iframe 的渐显过渡为 600ms，仅属于样机加载表现；应用页面的通用交互不应照搬为 600ms。
- 按钮、卡片和标签需要有可辨识的按下、选中、禁用、加载或完成状态。
- 页面切换或内容滚动不得导致浮动按钮覆盖正文，也不得丢失必要的搜索、筛选或滚动上下文。
- 尊重 `prefers-reduced-motion: reduce`；减少装饰动画，同时保留必要状态变化。

## 11. 响应式与无障碍

- 600px 以下视口以全屏应用布局呈现；桌面预览可以显示居中的手机宽度容器。
- 360px 以下进一步收紧横向内边距、头像和间距，文字允许换行，不得裁切。
- 页面内容不能依赖固定 375px 宽度；最窄视口应至少覆盖 320px。
- 长列表使用单一明确的主滚动区域；固定页头、底栏及操作栏不得与滚动内容争抢滚轮或手势。
- 底部留白使用 `env(safe-area-inset-bottom)`，保证真实设备安全区内的操作可见。
- 所有交互控件支持清晰的键盘焦点状态；表单具备可见标签和可读错误提示。
- 文字和状态须保持足够对比度；点位和路线在地图上不能仅靠颜色区别。

## 12. 页面验收清单

- [ ] 页面沿用浅色海洋主题、品牌蓝色和现有字体体系。
- [ ] 页面结构优先单列纵向阅读，标题、正文、状态和主操作层级清晰。
- [ ] 卡片圆角、边框、投影和图标风格与本规范一致。
- [ ] 320px、360px、375px、393px 宽度下无横向溢出或内容裁切。
- [ ] 桌面样机呈现比例正确，手机外框与应用实际内容尺寸匹配。
- [ ] 固定导航、悬浮助手、地图控件不遮挡正文或主要地图信息。
- [ ] 核心触控目标不小于 44px，焦点、禁用和完成状态清楚。
- [ ] 底部安全区、滚动边界、返回路径和异常空态均已检查。
- [ ] 装饰动效尊重减少动态偏好，主要交互仍可辨认。

## 13. 地图页结构与交互约定

### 页面目标

地图页以手绘园区底图为主要内容，帮助用户查找地点、识别地点类型、查看地点信息，并规划经过多个地点的游园路线。页面沿用原程序的浅色海洋主题和导航方式，地图画布始终保持为视觉主体。

### 页面结构

1. **顶部区域**：保留原程序的页面返回或地图导航状态；搜索框作为主要入口，支持按地点名称查找。
2. **分类筛选**：搜索框下方使用可横向滚动的标签，包含「全部、场馆、餐饮、休闲、礼品、卫生间、出入口」。默认选中「全部」，选中状态使用浅海蓝底和品牌蓝文字。
3. **地图画布**：占据页面可用主体区域，显示手绘底图和地点标记。缩放、居中等地图控制采用悬浮圆形按钮，固定在地图边缘并避开地点详情卡片。
4. **地点详情卡片**：选中地点后从底部展开，使用白底圆角卡片和柔和阴影。收起时展示地点名称及主要操作；展开时展示已有地点信息、全部类型标签和路线操作。
5. **底部导航**：延续原程序导航样式和当前地图选中态。详情卡片与路线面板需为导航和设备安全区留出空间。

### 地点与路线的视觉表达

- 普通地点标记使用浅海蓝和线性语义图标；地点序号和名称在当前缩放级别下保持可辨识。
- 多标签地点在地图上采用一个主图标，避免多个图标叠加；选中后的详情卡片展示全部类型标签。
- 选中地点通过品牌蓝描边、外环或名称提示强化状态，不只依靠颜色变化。
- 路线使用珊瑚色主线和白色衬底提升对比度，途经点以数字徽标标出顺序；地点到路网的接入段使用虚线。
- 标记密集时优先减少地图上的常驻文字，选中地点显示完整名称；不同地点仍须保持独立可点选。

### 主要交互状态

| 状态 | 页面反馈 |
| --- | --- |
| 初始浏览 | 展示完整地图、全部地点标记、搜索框和分类筛选；底部显示轻量路线入口。 |
| 搜索中 | 输入关键词后展示匹配地点；选择结果后定位并选中地图标记，打开地点详情卡片。 |
| 分类筛选 | 按所选类型突出符合条件的地点；无匹配结果时显示说明和「清除筛选」操作。 |
| 地点选中 | 地图标记突出显示，底部详情卡片展开；提供「加入路线」及「设为起点」等操作。 |
| 路线编辑 | 展示已选地点、起点和路线规划操作；支持移除途经地点及调整起点。 |
| 路线结果 | 地图显示有序路线和编号站点；结果卡片展示访问顺序与地图坐标距离，并提供清除或重新规划操作。 |
| 空结果或不可达 | 保留当前地图和筛选上下文，说明原因并提供清除筛选、调整地点或重试入口。 |

### 地图数据与静态演示边界

- 手绘 PNG 作为可见底图；底图和 SVG 使用相同的 `1800 × 2400` 坐标画布、`viewBox` 和宽高比例。
- SVG 作为透明的数据与命中层使用，不承担默认视觉展示。不得通过 `display: none` 隐藏仍需查询几何或响应点击的内容；应将不可见的交互图形与可见标记、路线渲染分层。
- 地点类型映射为「场馆、餐饮、休闲、礼品、卫生间、出入口」，地点可以同时具有多个标签。
- 页面仅呈现已有地图项目数据中的名称、类型和坐标，不补造营业时间、实时拥挤度或无障碍设施信息。
- 本期使用静态演示定位，不申请真实定位权限或接入后端。默认路线起点可使用「游客中心」；定位按钮提供回到演示起点或恢复地图视野的反馈。
- 当前地图没有比例尺，路线长度以地图坐标单位展示，不换算真实距离或预计耗时。
- 发布页面使用独立的轻量地点与路网数据，不直接加载包含编辑器信息和嵌入资源的完整项目文件。

## 14. 地图页开发步骤与验收

按以下顺序逐步实现。每一步完成后先验证当前阶段，再进入下一步；地图页入口和原有页面导航保持可返回。

### 最终验收补充

- [ ] 搜索、筛选、地点选中、详情卡片、路线编辑和路线结果均有清楚的状态反馈。
- [ ] 多标签地点在地图上不产生图标堆叠，详情中可以辨认全部标签。
- [ ] 透明 SVG 数据层不遮挡可见地图控件；地图缩放后命中位置仍与标记重合。
- [ ] 路线结果不显示虚构的实际距离、耗时或实时定位信息。
- [ ] 主要按钮触控区域至少为 44px；详情卡片、路线面板与底部导航互不遮挡。
